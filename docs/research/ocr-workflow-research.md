## 1. SubVoice: closest OCR-to-speech interaction reference

**C/D:** SubVoice is a macOS 14+ Swift application using ScreenCaptureKit, Apple Vision and AVSpeechSynthesizer; Intel uses system speech and the packaged Kokoro path is Apple Silicon only. It does not provide a Windows or Android host. Its README describes Vietnamese subtitles and offline narration, not translation into Vietnamese. The reported 177 tests and latency figures were not rerun here. [Pinned README](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/README.md).

**C, ROI/capture:** `ScreenCapturer` sets `SCStreamConfiguration.sourceRect` to the selected region and pixel dimensions to that region. It excludes its own app, disables cursor/audio capture, requests 60-Hz frames and uses queue depth three. A capture generation UUID prevents a superseded stream from becoming current after asynchronous startup; stop invalidates that generation. Restart attempts are bounded. This demonstrates an explicit host adapter and bounded capture lifecycle, not access to arbitrary protected content. [ScreenCapturer.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceApp/ScreenCapturer.swift).

**C, change gate:** `ChangeDetector` samples BGRA every two pixels, thresholds luminance at 0.75 and makes a 64-column brightness signature. A total bright-pixel fraction below 0.002 is blank. Otherwise the mean L1 column difference must exceed 0.002 and its ratio to the smaller old/new brightness must reach 0.60. This reduces inference on an unchanged subtitle over moving dark imagery. Bright scenery, dark/colored subtitles, outlines, karaoke and fades can violate this heuristic; its constants require subtitle fixtures, not blind adoption. `AppCoordinator` limits OCR submissions with an 80-ms interval and clears text dedup state on blank-region transitions. [ChangeDetector.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceCore/ChangeDetector.swift), [AppCoordinator.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceApp/AppCoordinator.swift).

**C, bounded OCR:** `OCREngine` has one running inference and one replaceable pending frame: new frames overwrite the pending one. Results carry a capture-session UUID. Reset drops pending work but cannot interrupt the running recognition. Vision runs `.accurate`, with configured language `vi-VT`, correction enabled and minimum text height 0.05; that Apple-specific identifier must not become a generic AniSub language tag. `OCRAssembler` filters confidence below 0.30, sorts top-to-bottom using Vision's lower-left coordinates, then left-to-right within 0.02 normalized vertical tolerance. Joining everything with spaces loses separate-speaker/line layout. [OCREngine.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceApp/OCREngine.swift), [OCRAssembler.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceCore/OCRAssembler.swift).

**C, temporal text dedup:** `TextGate` applies Unicode NFC, collapses whitespace and removes isolated punctuation/noise tokens. It rejects fewer than two characters or text without letters. Exact repeat is dropped; an exact prefix extension speaks only its suffix; normalized Levenshtein similarity at or above 0.90 is dropped. Blank frames clear the remembered sentence so later identical dialogue is eligible again. These are readable policies, but one-letter utterances, numbers-only dialogue, changed negation and near-identical names need counterexamples. OCR observation time is not a verified cue start, and text similarity is not cue identity. [TextGate.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceCore/TextGate.swift).

**C, speech and ownership:** `SpeechQueue` immediately starts the first string; while speaking it appends strings. On four pending strings it removes the oldest two, keeping the active speech. `finished()` takes the next FIFO item; `dropPending()` clears only waiting speech. This contradicts the README pipeline diagram's unconditional no-drop wording; executable policy is bounded loss under backlog. `RegionFocusPolicy` pauses when the owner window disappears, no longer contains the ROI, is covered by another window, or changes title when enabled. It does not require the owner to be the globally active app. However failed owner reanchoring permits unbound capture: AniSub should explicitly report that state rather than implying verified owner identity. [SpeechQueue.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceCore/SpeechQueue.swift), [RegionFocusPolicy.swift](https://github.com/hoanganhuynh/subvoice/blob/6f5bdefa81bc52eea3363f8bcb5be2ce5b90e59a/Sources/SubVoiceCore/RegionFocusPolicy.swift).

**Inference for AniSub:** preserve the separate image gate, text gate, latest-frame slot and actual speech callbacks. Do not reuse this string FIFO as the media-clock scheduler: it carries neither known cue expiry nor player seek/speed revisions. AniSub's session/revision contract, two-segment speech bound and five-second horizon remain authoritative. No repository license was detected, and root `LICENSE`, `LICENSE.md`, `LICENSE.txt` returned 404; copying code is blocked pending an explicit grant. A separately licensed Kokoro model does not license SubVoice itself.

## 2. RSTGameTranslation: Windows capture, OCR settling and context

**C/D:** Current `RST.csproj` targets `net9.0-windows10.0.19041.0`, WPF/Windows Forms and `win-x64`. `GraphicsCaptureService` uses Windows Graphics Capture, a two-frame free-threaded D3D11 pool, resize recreation and explicit disposal. It can return a clone of the last cached frame when no new frame exists, so a consumer needs frame freshness/observation metadata. Windows desktop code is not Android-compatible source. [RST.csproj](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/RST.csproj), [GraphicsCaptureService.cs](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/src/GraphicsCaptureService.cs).

**C:** `Logic.cs` exposes a 0.2-second minimum OCR interval, previous OCR hash/text and optional settle time before translation. It suppresses similar text and permits manually retrying the current translation by clearing the remembered hash/text. CJK matching combines character overlap, trigrams and length; space-delimited matching uses keyword similarity, Dice and word overlap, with early acceptance when a metric exceeds the threshold. This is game-overlay dedup, not proven subtitle dedup. The Vietnamese stopword list includes negation and common dialogue words, so a keyword-only early accept can hide meaningful changes. AniSub needs negation/name/number fixtures before adopting such suppression. [Logic.cs](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/src/Logic.cs).

**C:** Translation requests contain source/target languages, ID-bearing text blocks, recent original-text context and game information. Context pieces/minimum size are configurable and drawn from chat history. `ChatGptTranslationService` uses a system prompt plus input JSON and temperature 0.3; compatibility paths wrap plain/invalid JSON. Treat returned text as provider output requiring identity/schema validation, never as permission to alter scheduler state. The inspected logic logs requests/content: that pattern conflicts with AniSub's no-content-by-default diagnostics. `TextObject` dispatches speech to selected cloud/local backends, but does not establish media-clock timing. [ChatGptTranslationService.cs](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/src/ChatGptTranslationService.cs), [TextObject.cs](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/src/TextObject.cs).

**License discrepancy:** README's BSD badge conflicts with inspected `LICENSE.md`, which contains GPL v3. Record the actual license, resolve provenance before reuse and audit bundled OCR/TTS artifacts separately. README claims four speech backends; Supertonic SDK is MIT while the selected model is OpenRAIL-M. Neither is a blanket permission for other bundled engines. [Pinned LICENSE.md](https://github.com/thanhkeke97/RSTGameTranslation/blob/7c4274175db7a7cbc8a4a071c10491a7133286c1/LICENSE.md), [Supertonic-3 model card](https://huggingface.co/Supertone/supertonic-3/blob/main/README.md).

## 3. VideoLingo: terminology and offline alignment, not live orchestration

**C/D:** Current README uses Qwen3-ASR/ForcedAligner by default; WhisperX is an optional manual backend, not the current guaranteed default. Windows/macOS/Linux support is claimed for its desktop/browser workflow. These claims must not be imported from an older corpus snapshot. [Pinned README](https://github.com/Huanshere/VideoLingo/blob/01f843492759be9bbfd1a5cb697b799cc9de1609/README.md).

**C:** `_4_1_summarize.py` concatenates existing sentence chunks, truncates to configured summary length, loads `custom_terms.xlsx`, validates generated terminology entries with `src/tgt/note`, then appends custom entries. It includes relevant terms by case-insensitive substring matching. This is useful as a glossary schema, but substrings can match inside unrelated words; duplicates and conflicting target terms need explicit precedence. The existing-file guard preserves edited terminology on retry. The code also prints terminology content, unsuitable for AniSub default logs. [Terminology source](https://github.com/Huanshere/VideoLingo/blob/01f843492759be9bbfd1a5cb697b799cc9de1609/core/_4_1_summarize.py).

**C:** `translate_lines.py` supplies previous context, future context, summary and terminology to a shared prompt. It checks required numbered response items/subfields and retries at most three times. Faithful translation is first; optional expressive rewriting can fail back to the faithful result while stop cancellation propagates. Preserve original and both derived versions if evaluating this pattern. Future context exists in batch input; a live pipeline cannot wait indefinitely for it. ID cardinality validation is useful but does not prove translation meaning or timing. [translate_lines.py](https://github.com/Huanshere/VideoLingo/blob/01f843492759be9bbfd1a5cb697b799cc9de1609/core/translate_lines.py).

**C:** `_8_2_dub_chunks.py` computes gaps from neighboring start/end times and total source-audio duration, estimates spoken duration, decides acceptable speed factors and merges neighboring subtitle rows. That requires the full timeline and can reshape text to fit offline output. Borrow duration budgeting as an experiment; do not transplant batch merge/speed/render behavior into AniSub's live scheduler or infer unknown cue ends. Apache-2.0 code does not settle every ASR/TTS weight license. [Dubbing timing source](https://github.com/Huanshere/VideoLingo/blob/01f843492759be9bbfd1a5cb697b799cc9de1609/core/_8_2_dub_chunks.py).

## 5. Android capture boundaries and practical next evidence

**P:** MediaProjection exists from API 21, but consent is required for every capture session; Android 14 tokens/virtual-display creation are single-use and targeting 34+ adds the mediaProjection foreground-service permission/type. Stop callbacks must release capture resources. This does not imply a third-party app's decoded frames are available. Secure windows marked `FLAG_SECURE` cannot appear in screenshots/nonsecure displays. [Media projection contract](https://developer.android.com/media/grow/media-projection), [FLAG_SECURE reference](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE).

**P:** AudioPlaybackCapture starts at Android 10/API 29, requires RECORD_AUDIO plus approved MediaProjection and the same user profile. Captured-player usage must be media/game/unknown and effective capture policy must allow it; the most restrictive manifest/player policy wins. Therefore arbitrary-app audio ASR cannot be promised on API 23 and denial is not permission to silently switch input mode. [Official audio capture contract](https://developer.android.com/media/platform/av-capture).

**Design inference:** implement provider-neutral fake fixtures first: repeated cue after a blank gap; NFC/NFD Vietnamese; fades; changed negation/number/name; two-line dialogue; bright background; late inference after seek; old speech completion after revision invalidation; capture stop; and overflow with expired cues. Store OCR observations with confidence/ROI/provenance separately from known cue bounds. Attach glossary version and model revision to translation cache keys, use bounded past context, and keep raw text out of normal logs.

Then benchmark a small scene-OCR candidate on consented subtitle crops against the same fixtures on Windows and the actual target Android hardware, measuring p50/p95 latency, missed transitions, false dedup, memory, model-load cost and speech backlog. No selected model, downloaded artifact, engine benchmark, emulator smoke or hardware result exists yet. Exact model licenses, current installer/backend compatibility and secure-content behavior remain gates. Rollback is removal of this research document; no product behavior changed.
