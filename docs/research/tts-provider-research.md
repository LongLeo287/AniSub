# AniSub TTS provider research

Research date: 2026-10-06. Scope: standalone AniSub design; no AniBox integration, installation, model download, inference, voice enrollment, or remote mutation. This is a source audit, not a working feature or device benchmark. Read against `docs/system-design.md` and `docs/protocol.md`.

## Decision

Evaluate **VieNeu v3 Turbo first for Vietnamese**, using its CPU/ONNX SDK as the desktop reference. Evaluate **VoxCPM2 for Vietnamese/Thai desktop quality** when a suitable GPU profile is available. Keep **OmniVoice as a noncommercial research comparator**, because its pretrained model has a different license from its code. Treat Android/API 23 as a separate portability and device gate; no inspected repository establishes AniSub compatibility on P650.

All 18 supplied sheet candidates are accounted for below. Sheet row numbers identify the research inputs; their old descriptions are not evidence. “Docs” means README/root-license triage, sometimes an explicitly linked model card; “Code” means actual inference/lifecycle paths inspected. Authors' speed/quality numbers are upstream claims, never local measurements.

## Deep audit: VieNeu-TTS, row 84

Pinned source: [`85344322b7258b4e25479b692e8e3396baf9db34`](https://github.com/pnnbao97/VieNeu-TTS/tree/85344322b7258b4e25479b692e8e3396baf9db34). Package metadata says **vieneu 3.8.3**, Python >=3.10. CPU dependencies include ONNX Runtime >=1.20, Rust-based sea-g2p, tokenizers, soundfile, soxr and kaldi-native-fbank; the package also includes Gradio/librosa. CUDA adds PyTorch/torchaudio 2.8 and transformers. A torch-free CPU path is therefore not a tiny dependency-free Android library. [Pinned dependency manifest](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/pyproject.toml).

The factory selects v3 Turbo by default. `infer(text, voice=...)` returns complete audio; `infer_stream(...)` yields float32 PCM at 48 kHz. CPU delegates to the engine's frame iterator; CUDA uses a shared scheduler. `style` is accepted but ignored. The GPU iterator closes handles in cleanup; scheduler `close()` marks a request cancelled and suppresses further delivery, while provider `close()` shuts its scheduler down. This is cooperative cancellation, not proof that an in-flight kernel stops instantly. AniSub must gate every chunk by generation/revision and stop its own output immediately. [Factory](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/src/vieneu/factory.py), [SDK API](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/src/vieneu/v3turbo.py), [scheduler](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/src/vieneu/v3_turbo_serve/stream.py).

The GPU engine loads the separate MOSS codec using `trust_remote_code=True`. Preset/model loading can fetch Hub assets; cloning adds reference-processing artifacts. `prepare` must use reviewed local paths and a manifest covering every artifact, with explicit download consent, rather than executing the upstream convenience constructor blindly. [Engine](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/src/vieneu/_v3_turbo_engine/inference_v3_turbo.py).

Code's [root license](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/LICENSE) is Apache-2.0. The [Turbo model card](https://huggingface.co/pnnbao-ump/VieNeu-TTS-v3-Turbo/blob/61b85e3d937fbbacb387714180e8182823512523/README.md) independently applies Apache-2.0 to weights, ONNX exports and bundled preset assets and asserts appropriate speaker permissions. This is the publisher's representation, not an independent rights audit. Card describes SDK 3.7.1/23 voices while current README describes 25: enumerate the pinned SDK's roster instead of hard-coding an old count. Codec [model card](https://huggingface.co/OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano/blob/6aa02b01e445cc585582cf0ba480bc3ea6c8dd68/README.md) labels Apache-2.0; retain separate notices.

[Current README](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/README.md) identifies Vietnamese/English v3 Turbo as the open release and v4 as proprietary API-only. Its RTX 3060 and desktop CPU latency claims do not establish subtitle deadlines or ARM speed. **Nano preview** is a different 48M flow model, 24 kHz, lower bilingual quality; its `infer_stream` completes a text chunk before yielding, not frame streaming. Its Android/edge positioning remains a claim pending frontend, ABI and device validation. [Nano card, revision `aba295eb96a6fa6003ebe417cc1f2802a7adc1dc`](https://huggingface.co/pnnbao-ump/VieNeu-TTS-v3-Nano/blob/aba295eb96a6fa6003ebe417cc1f2802a7adc1dc/README.md), [Nano code](https://github.com/pnnbao97/VieNeu-TTS/blob/85344322b7258b4e25479b692e8e3396baf9db34/src/vieneu/v3nano.py).

Verdict: priority Vietnamese desktop adapter; Nano is a later low-resource comparison. Thai capability is not established for either VieNeu variant.

Do not project SDK parity onto the audio.cpp port. At commit `d894789017cfd349581dec9e79752e0e4562fbf3`, its `vieneu_v3_turbo` documentation says streaming is not yet ported and CAM++ speaker extraction is absent; accurate cloning requires supplied speaker embeddings. SEA-G2P and preset assets also need their own packaging. [Pinned port documentation](https://github.com/0xShug0/audio.cpp/blob/d894789017cfd349581dec9e79752e0e4562fbf3/docs/community_models/vieneu_v3_turbo.md). See the separate native-runtime report for handle ownership and cancellation limitations.

Native-port parity caveat: [audio.cpp's VieNeu port at `d894789017cfd349581dec9e79752e0e4562fbf3`](https://github.com/0xShug0/audio.cpp/blob/d894789017cfd349581dec9e79752e0e4562fbf3/docs/community_models/vieneu_v3_turbo.md) identifies family `vieneu_v3_turbo` (legacy alias `vietneu_tts`) as offline-only. Streaming and CAM++ speaker encoding are not yet ported; cloning needs an external speaker embedding. Text requires SEA-G2P phonemes or the separately supplied Rust/C-ABI frontend and dictionary. Upstream Python streaming cannot be advertised as native-port functionality. Benchmark these as distinct providers with separate capabilities and manifests.

## Deep audit: OmniVoice, row 414

Pinned source: [`08be0b4ccbac3e13e374e86fbfead4b4cac343e2`](https://github.com/k2-fsa/OmniVoice/tree/08be0b4ccbac3e13e374e86fbfead4b4cac343e2), package **0.2.1**. Python >=3.10; torch/torchaudio >=2.4, transformers >=5.3, accelerate, librosa and Gradio are declared. Text normalization is an optional WeTextProcessing/num2words extra, not a guarantee of correct Vietnamese/Thai number reading. [Dependencies](https://github.com/k2-fsa/OmniVoice/blob/08be0b4ccbac3e13e374e86fbfead4b4cac343e2/pyproject.toml).

`OmniVoice.from_pretrained(...)` loads text and audio tokenizers; absent a local audio-tokenizer directory it resolves `eustlb/higgs-audio-v2-tokenizer`. Missing reference transcript may trigger Whisper ASR loading. `generate(text, language, ref_audio/ref_text or voice_clone_prompt, instruct, duration, speed, ...)` returns a list of complete arrays, usually 24 kHz. Internal long-text chunk generation collects outputs; the inspected public method offers neither incremental PCM callback nor cancellation token. Treat this adapter as full-utterance and discard retired results; process isolation can provide bounded recovery if a worker hangs. `duration` overrides `speed` through target frame counts, with subsequent padding/fades: measure final PCM length and intelligibility rather than promising exact cue fit. [Inspected loading/generation code](https://github.com/k2-fsa/OmniVoice/blob/08be0b4ccbac3e13e374e86fbfead4b4cac343e2/omnivoice/models/omnivoice.py).

The [language table](https://github.com/k2-fsa/OmniVoice/blob/08be0b4ccbac3e13e374e86fbfead4b4cac343e2/docs/languages.md) explicitly lists `vi` and `th`. The [README](https://github.com/k2-fsa/OmniVoice/blob/08be0b4ccbac3e13e374e86fbfead4b4cac343e2/README.md) describes cloning, voice design and automatic voice selection, but warns voice design was trained on Chinese/English and may be unstable elsewhere. Its H100 batch/FlashInfer figures measure a Chinese testset, not Vietnamese subtitle latency. No Android viability was verified.

Crucial distinction: [root code LICENSE](https://github.com/k2-fsa/OmniVoice/blob/08be0b4ccbac3e13e374e86fbfead4b4cac343e2/LICENSE) is Apache-2.0, while the [official pretrained-model card, revision `c5fdb5ccb189668d56333f77ba2629f4cd7535f4`](https://huggingface.co/k2-fsa/OmniVoice/blob/c5fdb5ccb189668d56333f77ba2629f4cd7535f4/README.md) explicitly says CC-BY-NC because of training-data constraints. The card does not specify a CC version there. [Separate Higgs codec card](https://huggingface.co/eustlb/higgs-audio-v2-tokenizer/blob/528e871c2a26c4f0f7773b9754e2e1acae20899d/README.md) requires its own artifact-level license review; empty license metadata is not permission.

Verdict: valuable multilingual noncommercial research comparison; not an assumed commercial production default.

## Concrete AniSub adapter and timing implications

Proposed internal interface, not a new wire protocol: `probe(hostProfile) -> capabilities`; `prepare(manifest, lease, localOnly)`; `synthesize(SpeechJob, cancelToken, boundedPcmSink)`; `cancel(jobId)`; `release(lease)`. Capabilities must distinguish FULL_UTTERANCE, COMPLETED_TEXT_CHUNKS and INCREMENTAL_PCM, supported tested languages, sample format, rate/duration controls, cancellation mode, host and measured memory profile.

`SpeechJob` carries job/speech/cue IDs, session/revision, language, normalized speech text, immutable voice/model versions, optional known media bounds, deadline and max output duration. Provider callbacks return identifiers, monotonic metrics and ordered PCM chunks; providers do not change playback state, invent cue timestamps or emit public STARTED on inference submission. No subtitle content in default logs.

Coordinator owns one bounded output path, revision guards before inference/chunk enqueue/output/callback, and protocol's active-speech ledger. STOP/seek/input/speed changes close the PCM sink and stop output even if inference continues. Exactly one FINISHED closes each accepted STARTED; stale terminal cleanup may close only its original ledger entry. Current limits remain two speech segments/five-second queued media horizon. Add a provisional 1 MiB PCM queue cap and stop accepting audio when full; tune by evidence.

With known cue bounds, map remaining media time through playback speed to a wall-time budget. Drop already expired jobs; skip or cancel overlong speech according to explicit policy rather than accumulating delay. Unknown bounds do not justify fabricated duration. OmniVoice duration control is optional and needs intelligibility testing; VieNeu streaming improves first PCM but does not guarantee utterance completion within a subtitle window. Generated audio/SRT alignment is relative to the synthesized output, not original-media cue timing.

## Benchmark gate before provider selection

After explicit model-download authorization, pin all dependency and weight/codec/voice revisions plus digests/sizes. Run 100 Vietnamese cues covering 1–3 word replies, regional vocabulary, accents, names, numerals, dates, punctuation and En–Vi switching. Add a separately scored Thai set only for providers with verified language declarations; use authorized voices.

On each desktop CPU/GPU profile measure cold load, first PCM, first audible output, full synthesis, RTF, p50/p95 deadline misses, final duration, peak RAM/VRAM, storage and sustained thermal behavior. Report batch throughput separately from one-session latency. Native listening review plus independent ASR WER/CER checks quantify omissions/repetitions; ASR agreement alone is not naturalness evidence.

Inject cancellation during load/prefill/decode/output, 20 rapid seeks, pause/resume, speed changes, disconnect, stale revisions, queue pressure and worker failure. Proposed gates: zero obsolete audible chunks after output-stop acknowledgement; exactly-once terminal cleanup; queues remain bounded; recovery releases leases. Android/API 23 requires frontend/ORT/JNI ABI and real-device memory/thermal/output tests independently. No provider passes these gates in this research-only phase.
